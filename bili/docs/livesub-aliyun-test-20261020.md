# 固定主播录像：阿里云字幕推流测试（2026-10-20）

## 结论

固定主播 `reikokobayakawa.official` 的录像完成 **90 秒本地输出 + 180 秒 B 站实际推流**。
Nemotron 语音识别、阿里云日译中、顶部字幕绘制和 RTMP 输出全链路可运行，
已从 B 站观众端取回含中文字幕的画面。单次短时样本下，5 秒缓冲足以覆盖本次
切句后的翻译与队列等待；未测量观众端总延迟或逐句音画对齐误差。

字幕质量仍受口语识别、切句和翻译术语影响，不等于准确率验收。
测试后关闭本次临时开启的 B 站直播间；固定目标及自动值守设置未改动，自动推流仍不启用字幕。

## 样本与设置

- 文件：`~/pik/TikTok/reikokobayakawa.official_小早川怜子🥀🎠/reikokobayakawa.official_小早川怜子🥀🎠_20260909_140837.mp4`。
- 原片约 600 秒，720×1280，H.264 + AAC，含多人连麦；取开头分别测试 90 秒和 180 秒。
- 机器：4 核 Neoverse-N1，约 24 GB 内存。
- ASR：Nemotron 3.5 streaming 0.6B Q8_0，CPU 2 线程，`ja-JP`。
- 翻译：`--mt-backend aliyun`，TranslateGeneral，`ja → zh`，无上下文和术语表。
- 画面缓冲：`--delay 5`；字幕顶部居中，`y=120`，日文在上、最近一句中文在下。
- 输出：25 fps，x264 `veryfast`，视频目标 2500 kbps，AAC 128 kbps。
- 测试时持有现有控制锁，避免值守或管理页同时起流；未停止其他录制任务。

| 项目 | 结果 |
|---|---|
| 本地输出 | 90.141 秒 FLV，约 30.2 MB，取流与编码进程退出码均为 0 |
| B 站推流 | 180.160 秒，4501 帧，FFmpeg `progress=end`，进程正常退出 |
| B 站接收验证 | 房间 `9337260` 在测试中为 `live_status=1`，观众端成功截取含顶部中文字幕的画面 |
| 实际推流测试墙钟时间 | 186.4 秒（含模型启动、缓冲及收尾） |
| 翻译成功句数 | 25 |
| 翻译耗时 | 平均约 0.34 秒，范围约 0.2～0.5 秒 |
| 翻译失败 / 晚于字幕排期 | 0 / 0 |
| FFmpeg 复制帧 / 丢帧计数 | 0 / 0 |
| 稳定阶段 CPU | 平均 144.0%，最高采样 153.5%（100% = 1 核，平均占四核机器约 36%） |
| 稳定阶段内存 | 进程树 RSS 合计平均 1360.9 MiB，最高 1363.5 MiB（约 1.33 GiB） |

耗时由日志中的 0.1 秒精度数值汇总，不含 ASR 等待与视频分发。
“晚于排期”为翻译完成时间超过“切句提交时间 + 5 秒”，不能证明字幕与原始语音完全同步。
CPU 与 RSS 为字幕脚本及其两个 FFmpeg 子进程的合计，每约 5 秒采样，
统计第 20～180 秒的 32 个样本；不含整机其他服务，RSS 可能重复计入共享内存。
采样最高值不等于瞬时峰值，FFmpeg 丢帧计数也不代表网络端完全没有损失。

## 字幕效果

- 本地预览和 B 站回拉画面均能看到顶部白字字幕，本样本的顶部黑边提供了足够显示空间。
- 简单句可用，例如「どちらでも大丈夫です」→「哪个都可以。」。
- 直播用语不稳定，例如「初見さん」出现“初见先生”等不合语境的翻译；相同原文的两次测试译文也有差别。
- 识别出的「メンバーレベル十分ってるから…」等句子存在明显歧义，中文会随错误原文偏离。
- 日文显示当前识别片段，中文显示最近完成的译文，两行不一定属于同一句；
  本次没有人工逐句对照音频，也未计算识别准确率、翻译评分或精确延迟。

## 复现与产物

本地复现（在交互式 Bash 中执行，实际调用阿里云服务）：

```bash
source ~/.bashrc
python3 bili/livesub.py reikokobayakawa.official \
  --source "$HOME/pik/TikTok/reikokobayakawa.official_小早川怜子🥀🎠/reikokobayakawa.official_小早川怜子🥀🎠_20260909_140837.mp4" \
  --out /tmp/reiko-aliyun.flv --duration 90 --delay 5 \
  --mt-backend aliyun --workdir /tmp/reiko-aliyun
```

实际推流使用同一原片，改为 `--out rtmp --duration 180`；需先开播并同步推流码，
确认没有其他推流进程，结束后关闭仅为测试开启的直播间。

本机产物在 `recordings/livesub-test-20261020/`（Git 忽略，不提交媒体与运行日志）：

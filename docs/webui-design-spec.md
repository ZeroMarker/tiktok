# WebUI 设计规范

适用范围：本仓库的「直播录制中心」WebUI（`webui/frontend/`）。Bilibili 独立 WebUI 不在本规范范围内。

本文以现有页面和样式为基线，供页面设计、组件开发与验收使用。标为「现有」的内容描述当前实现；标为「要求」的内容约束后续新增和改造，不代表现有页面已全部满足。前端为原生 Web Components（Lit 3，ESM + import map，**无构建链**）；设计值以 [styles.js](../webui/frontend/styles.js) 为准，平台配置以 [platforms.js](../webui/frontend/config/platforms.js) 为准；变更时同步维护本文。

## 1. 产品目标与设计原则

用户应能快速判断哪些频道正在直播、哪些任务需要处理、磁盘是否够用，并完成新建任务、暂停、继续、查看日志和管理录制文件。

- **状态先行**：实时录制、任务运行和服务连接分别表达，不能用「运行中」代替「直播中」。
- **操作明确**：按钮使用具体动词；影响录制或删除数据的操作说明对象与结果。
- **视觉一致**：延续 Material Expressive 风格的深色表面、薄荷绿主色、圆角容器和短促动效，复用现有变量与组件。
- **信息有层次**：关键数量优先展示；频道、状态和操作位于任务卡片；日志和技术字段放在详情页。
- **反馈可恢复**：加载、空数据、失败、部分同步失败和离线使用独立提示，提供可执行的下一步。

## 2. 信息架构

现有页面使用 hash 路由，主导航固定为四个入口；任务详情归属「任务」导航。

| 页面 | 路由 | 内容与主要操作 |
| --- | --- | --- |
| 概览 | `#/` | 实时状态、四项指标、系统信息、平台分布、最近任务与最近文件 |
| 任务 | `#/tasks` | 搜索与筛选、任务列表、日志入口、暂停／继续／重启／删除 |
| 任务详情 | `#/tasks/:unit` | 任务状态与属性、控制操作、日志、录制文件入口 |
| 录制文件 | `#/library` | 搜索与筛选、分组浏览、播放、下载与删除 |
| 新建任务 | `#/new` | 平台选择、频道或直播地址、录制画质、开始录制 |

全局结构为：顶部栏 → 工作空间（主导航与页面内容）→ 全局确认框／Toast。桌面主导航为左侧栏，≤920px 时变为横向导航；页面内容顶部显示连接与同步提示。提供键盘可用的「跳转到页面内容」入口，首次同步完成前展示加载提示。顶部栏包含产品名称、服务状态、刷新及可用时的安装入口。

要求：导航选中态与实际路由一致；详情页始终提供返回任务列表的入口；新增页面应先确定所属导航，避免增加重复入口。

## 4. 字体、间距与形状

### 4.1 字体与字号（现有）

字体栈：`Google Sans Text → Noto Sans → Inter → ui-sans-serif → system-ui → PingFang SC → Microsoft YaHei → sans-serif`。字体按本机可用情况回退，不保证所有设备显示相同字形。

| 层级 | 字号 | 使用位置 |
| --- | --- | --- |
| 实时核心数字 | 52px；≤680px 时 40px；≤440px 时 34px | 概览 Hero |
| 指标数字 | 30px；≤440px 时 24px | 指标卡 |
| 产品标题 | 24px；≤440px 时 17px | 顶部栏 |
| 对话框标题 | 16px | 确认框 |
| 面板标题 | 17px | 内容分区 |
| 默认正文 | 14px，行高 1.5 | 页面基础文字 |
| 表单与按钮 | 常规 13px，紧凑 11–12px | 输入和操作 |
| 次级信息 | 11–12px | 状态、元数据、说明 |
| 辅助标签 | 9–10px | 平台标签、计数、分区副标题 |
| 日志 | 12px，行高 1.65 | 等宽预格式文本 |

要求：关键字段和操作不能仅以辅助字号呈现；新增正文优先使用 13–14px。频繁更新的数字使用 `font-variant-numeric: tabular-nums`，避免位数变化引起跳动。

### 4.2 间距与容器

现有常用间距为 4、6、8、10、12、14、16、18、20、24、28、32px。新增布局优先采用 4px 倍数；密集工具栏可沿用现有 6／10／14px 间距。

- 页面外壳最大宽度 1520px，居中；桌面水平内边距 32px。
- 桌面侧栏宽 184px、内容间距 28px（≤1100px 时为 160px／20px）；指标卡间距 14px，任务列表间距 10px，详情双栏间距 20px。
- 普通面板内边距 24px、顶部间距 20px；Hero 桌面内边距 32px，≤1100px 时 24px。
- 底部留白包含 `env(safe-area-inset-bottom)`，适配安装后的移动端窗口。

### 4.3 圆角与层级（现有）

| 变量或对象 | 值 |
| --- | --- |
| `--s-sm` | 10px |
| `--s-md` | 16px |
| `--s-lg` | 24px |
| `--s-xl` | 32px |
| `--s-full` | 999px |
| 普通面板／Hero | 20px／24px（≤440px 时 18px／20px） |
| 顶部栏 | 22px |
| 基础阴影 | `0 10px 34px rgba(0,0,0,.2)` |
| 悬停阴影 | `0 18px 44px rgba(0,0,0,.28)` |
| 顶部栏／确认框／Toast 层级 | `z-index: 40 / 60 / 70` |

要求：同类组件沿用相同形状；装饰性非对称圆角仅沿用既有指标卡和平台卡样式。阴影用于区分层级，边框仍需保持可辨。

## 5. 组件规范

| 组件 | 现有基线 | 后续设计要求 |
| --- | --- | --- |
| 主导航 | 桌面侧栏、窄屏横向滚动容器，按钮最小高度 48px（≤440px 为 44px）；选中为主色容器底与指示点 | 使用短标签；选中态提供 `aria-current="page"` |
| 主按钮 | 最小高度 40px、16px 圆角、主色渐变 | 一个操作区域突出一个主动作；请求中显示「…中」并禁用重复提交 |
| 次级／危险按钮 | `.secondary`／`.danger`；紧凑操作高度 32–36px | 危险动作使用具体动词，并与普通操作保持可辨的视觉差异 |
| 输入框／下拉框 | 深色表面、16px 圆角；常规字段最小高度 40px | 必须有标签或可访问名称；提示与错误靠近对应字段 |
| 选择控件 | 平台卡、分段画质、筛选 Chip | 选中态同时表达样式和语义；单选组支持键盘切换 |
| 指标卡 | 桌面四列，数字、标签、图标和说明 | 说明统计范围；未知值用「—」，不以零冒充成功获取的数据 |
| 任务卡片 | 平台标识、频道、任务状态、直播状态、操作 | 长频道名截断并可查看完整值；等待请求或停止收尾期间禁用该任务操作 |
| 文件分组与行 | 分组折叠、计数、文件名、元数据和操作 | 展开状态可感知；播放、下载、删除保持独立入口 |
| 内嵌播放器 | 位于文件浏览器内，视频宽度 100%、最大高度 52vh | 使用原生播放控制；显示当前文件名与关闭入口 |
| 日志面板 | 常规高度 370px，≤440px 时 320px；默认换行 | 长日志在面板内滚动；刷新不能妨碍复制、阅读和定位错误 |
| 确认框 | 最大宽度 440px、内边距 24px、32px 圆角 | 标题说明动作，正文说明对象与影响；提供取消、Escape 和完整焦点管理 |
| Toast | 默认显示 2500ms；桌面右下、窄屏底部通栏 | 用于短反馈；需要用户持续处理的错误另用常驻提示 |

图标统一通过 [app-icon.js](../webui/frontend/components/app-icon.js) 使用，基础尺寸 18px；导航 17px、顶部操作 16px。装饰图标隐藏于辅助技术；仅图标按钮必须保留可访问名称。

## 6. 状态与交互

### 6.1 任务与直播状态

现有映射由 [utils.js](../webui/frontend/utils.js) 管理；任务生命周期与直播检测结果是两个维度，应并列展示。

| 维度 | 数据值 | 显示与语义 |
| --- | --- | --- |
| 任务 | `active/running` | 运行中，绿色；可能仍在等待开播 |
| 任务 | `active/activating` | 启动中，警告色 |
| 任务 | `active/deactivating` | 停止中，信息色；暂停按钮显示「暂停中…」 |
| 任务 | `paused` | 已暂停，中性色；提供「继续」 |
| 任务 | `failed` | 失败，错误色 |
| 任务 | `inactive/dead` | 已停止，中性色 |
| 直播 | `live` | 直播中，直播强调色 |
| 直播 | `waiting` | 等待开播，警告色 |
| 直播 | `offline` | 未开播，中性色；区别于页面离线 |
| 直播 | `paused` | 已暂停，中性色 |
| 直播 | 其他或缺失 | 直播状态未知，信息色 |

要求：操作请求被接受与实际状态完成分开表达，最终状态以服务端刷新为准。删除任务需明确「停止并移除任务，保留录制文件」；删除文件需明确文件名与不可恢复的结果。暂停、重启和删除沿用确认流程，继续任务直接执行。

### 6.2 新建任务

现有默认平台为 TikTok、画质为「原画」，支持原画／1080p／720p／480p。平台切换时同步更新频道输入示例和说明。

提交前去除输入首尾空格；空输入提示补全；同平台同目标已有任务时提示重复，若已暂停则引导到任务列表继续。请求期间显示「创建中…」并禁用提交；失败保留输入并显示错误；成功进入新任务详情。

### 6.3 加载、空态与连接

| 场景 | 设计要求 |
| --- | --- |
| 首次加载 | 显示加载提示或占位，避免先显示「暂无任务」造成误判 |
| 正常空数据 | 说明暂无内容，并提供新建任务等适合当前页面的入口 |
| 筛选无结果 | 说明无匹配结果，并允许调整或清除筛选 |
| 单模块失败 | 就地显示错误与重试，其他可用区域继续使用 |
| 部分同步失败 | 全局提示失败模块，提供重新同步入口 |
| 页面离线 | 标明「显示缓存」或「等待连接」，展示最近同步时间；不得将旧数据标为实时 |
| 操作失败 | 保留用户上下文，提供具体错误；不得显示成功状态 |

现有 `ConnectionBanner` 与 `appState` 区分离线和部分同步失败，并提供重试。PWA 可离线打开界面；数据展示取决于已加载状态，不能据此承诺跨重启的数据持久缓存或离线执行操作。

### 6.4 数据表达

字节值复用 `fmtBytes`，按 1024 进位，MB 及以上保留一位小数；时间复用现有格式函数。百分比、时间和字节数明确单位，未知值显示「—」或具体的未知状态。

平台分布卡片按全部平台任务总数计算占比，条宽使用未取整的百分比，文字四舍五入为整数（因此显示值之和可能不等于 100%）。同时显示任务数；点击卡片进入对应平台的任务筛选。桌面三列、≤680px 时两列。

## 7. 响应式布局

断点使用包含边界的 `max-width`，较小断点覆盖较大断点。

| 视口宽度 | 现有布局规则 |
| --- | --- |
| >920px | 左侧主导航；指标四列；详情 `1.3fr / .7fr` 双栏；任务操作位于右侧 |
| ≤920px | 页面水平内边距 20px；主导航变为横向；指标两列；详情单栏；任务操作换到下一行 |
| ≤680px | 水平内边距 16px；导航可横向滚动；面板内边距 18px；直播状态卡独占一行；平台选择三列；创建表单单列 |
| ≤440px | 水平内边距 12px；隐藏时钟与产品副标题；顶部操作仅图标；面板内边距 16px；文件元数据换行；Toast 底部通栏 |

平台选择桌面 CSS 使用六列，当前配置包含六个平台；平台数量以配置为准。

要求：320px 宽屏幕可完成核心任务；导航、日志等局部区域可滚动，页面主体不产生意外横向滚动。长文件名、长频道名和错误文本应截断、换行或在局部滚动容器内展示，操作不能被挤出视口。

## 8. 动效与无障碍

现有基础过渡为 `150ms cubic-bezier(.2,0,0,1)`；按钮按下缩放至 `.98`，卡片悬停轻微上移，连接与录制圆点使用脉冲动效。

要求：动效用于反馈，不延迟提交或导航。遵循 `prefers-reduced-motion`，关闭非必要的循环动画和位移动效。现有减弱动画规则覆盖全部动画与过渡，并取消按钮按下及任务／指标卡悬停位移。

无障碍验收要求：

- 所有操作可通过键盘完成；可见焦点使用现有 2px 信息色轮廓与 2px 偏移。
- 新增普通正文对比度至少 4.5:1，大号文字至少 3:1；关键控件边界与焦点指示至少 3:1。透明背景按最终叠加色检查。
- 触屏主操作优先提供至少 44px × 44px 点击区域；现有 32–40px 紧凑按钮不视为已满足该要求。
- 表单标签关联控件；错误能被辅助技术感知；选择组支持方向键与明确的选中状态。
- 对话框打开时移动焦点到合适元素，限制焦点在框内，关闭后还原焦点；支持 Escape 取消。
- Toast 使用温和播报，重要错误使用明确提示；自动刷新不反复播报整页，也不抢占焦点。

## 9. 当前实现与规范的差距

以下事项仍是后续改造的验收项：

- 确认框已有 dialog 语义、标题关联和 Escape 关闭，尚缺焦点进入、焦点约束与关闭后还原。
- 平台与画质选择已有 radio 语义，尚缺完整的方向键切换和单选组焦点管理。
- 部分字号及紧凑按钮需要复核移动端可读性、触控区域和最终渲染色对比度。
- 任务详情仍有「systemd 单元列表」「Journal」等历史文案，暂停／重启确认框仍有「最长 30 秒」描述。应按当前进程内录制模型与真实收尾行为更新，避免误导用户。

## 10. 开发交付与验收

页面编排位于 `frontend/views/`，领域组件位于 `frontend/components/`，共享状态位于
`frontend/stores/`，动作在 `frontend/actions/`。组件基于 Lit 3：`class extends BaseElement`
（[base.js](../webui/frontend/base.js)）+ `customElements.define()`；响应式属性用
`static properties`（**不用装饰器**），样式用 `static styles` + `css` 标签模板。
新功能优先复用组件、变量、格式化函数和确认／反馈入口；新增共享变量时说明语义并更新本规范。

### Shadow DOM 与 light DOM 的混用

原则：**要参与父级布局或级联的组件用 light DOM，自包含的组件用 shadow DOM。**

- light DOM 组件（`LightElement`，`frontend/base.js`）：`app-header`、`app-nav`、`app-icon`、
  `metric-card`、`task-card`、`task-list`、`task-filters`、`task-creation-form`、`file-row`
  与五个 view。内容落在所在地（`app-root` 的 shadow root）的文档流里，因此祖先选择器与父布局
  照常生效；它们的样式来自所在地的共享样式表，**不要**给它们写 `static styles`。
- shadow DOM 组件（默认 `BaseElement`）：`app-root`、`connection-banner`、`global-feedback`、
  `log-panel`、`file-browser`、`file-group`、`file-toolbar`、`media-player`。它们自带完整样式，
  无祖先依赖，样式写在各自的 `static styles`。

结构性约定集中在 [styles.js](../webui/frontend/styles.js)：需要「布局透明」的 light DOM 宿主用
`display:contents`（`app-header`、`app-nav`、`metric-card`、`task-card`、`task-list`、
`task-filters`、`file-row`、各 view），指标卡位置配色用 `metric-card:nth-child(n) .stat…`。
新增 light DOM 组件时，把它的宿主显示方式与位置规则一起写进该文件。
